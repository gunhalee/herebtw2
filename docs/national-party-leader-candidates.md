# 전국 당대표 후보 운영 설계

## 동작 원칙

- `candidates.council_type`은 `당대표`를 허용한다.
- 당대표 후보는 `district = '전국'`으로 저장하고 지방의회 선거구 칼럼은 비워 둔다.
- 공개 후보 목록에서는 사용자의 지역 후보 다음에 전국 당대표 후보를 항상 표시한다.
- 화면 표기는 기존 후보 카드 규칙을 재사용해 `전국 · 당대표 후보`가 된다.
- 당대표 후보의 대시보드는 2026년 7월 1일 기준 16개 시·도와 전환 전 광주·전남 코드 2개를 커버리지로 사용한다.
- 게시글 원본을 후보마다 다시 조회하지 않고 기존 `candidate_post_inbox` 투영과 커서 페이지네이션을 사용한다.

## 후보 등록 필드

| 필드 | 값 |
| --- | --- |
| `name` | 후보명 |
| `district` | `전국` |
| `council_type` | `당대표` |
| `local_council_district` | `null` |
| `metro_council_district` | `null` |
| `photo_url` | 공개 후보 사진 URL |
| `email` | 후보 로그인·알림 이메일 |
| `auth_user_id` | 후보 로그인 계정의 Auth 사용자 ID |
| `is_active` | 공개 준비가 끝난 뒤 `true` |

첫 메시지는 기존 후보 온보딩 또는 운영자 등록 흐름으로 만들고 `first_message_id`에 연결한다.

## 커버리지 적용

후보 행을 등록한 뒤 먼저 dry-run 결과를 검토한다.

```powershell
npm run candidate:coverage:dry-run -- --candidate-id=<후보 UUID>
```

당대표 후보가 현재 시·도 코드 16개와 과거 글 호환 코드 2개에 `coverageType: "province"`로 매핑되는지 확인한 뒤 적용한다.

```powershell
npm run candidate:coverage:apply -- --candidate-id=<후보 UUID>
```

커버리지를 교체하면 기존 운영 구조가 현재 선거 주기의 공개 시민 글을 라우팅 큐에 다시 넣는다. 후보 대시보드 조회는 최대 50개 커서 페이지로 제한되므로 전체 글 수가 늘어나도 한 요청의 응답 크기는 증가하지 않는다.

## 공개 전 검증

1. 지역 코드가 있는 공개 후보 API에서 지역 후보 다음에 당대표 후보가 반환되는지 확인한다.
2. 위치 코드가 없는 후보 목록에서도 당대표 후보가 반환되는지 확인한다.
3. 후보 카드가 `전국 · 당대표 후보`로 표시되는지 확인한다.
4. `npm run candidate:verify:strict`로 미매핑 활성 후보가 없는지 확인한다.
5. 당대표 후보 계정으로 대시보드에 로그인해 서로 다른 시·도의 글이 커서 페이지로 조회되는지 확인한다.

## 규모와 운영 주의점

전국 후보 한 명을 추가하면 현재 선거 주기의 공개 시민 글마다 후보 inbox 행이 최대 한 개씩 추가된다. 전국 후보 수가 늘면 저장량은 `공개 글 수 × 전국 후보 수`에 비례하므로, 전국 후보는 실제 경선 후보만 활성화하고 사퇴·종료 후보는 즉시 비활성화한다.
